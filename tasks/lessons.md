# Project lessons

## Migration of the data layer (Phase 1)

- Status enum changed from `nodata` (legacy) to `no-data` (JSON Canvas extension). Three places need to follow that change in lockstep: (1) `index.html` `data-filter` attribute on the filter button, (2) `STATUS_COLOR` map in `js/viewer.js`, (3) `STATUSES` array in `js/nodes.js`. Forgetting any one leaves a status that the viewer renders as `unsolved` (fallback) and the filter button cannot turn off.
- The old `kind: "bezier"` arrow rendering maps to JSON Canvas `routing: "smooth"`. The i18n key stays `arrow_kind_bezier` for the dropdown label because the user-facing word is still "Bezier"; only the internal value changed.
- Edge endpoint anchoring: JSON Canvas spec has `fromSide`/`toSide` which take cardinal sides, but we also persist a `bindings.from.fixedPoint` so an edge can attach to any normalised point on the node rect, not just the four midpoints. The side keeps the legacy shape readable; the binding is the source of truth used by the renderer.
- `loadCanvas()` returns `{ nodes: Map, edges: Map, fellBack: boolean }`. The `fellBack` flag is how `app.js` decides to surface the migration banner. Without that boolean the only way to know we used the legacy path was to refetch `data/canvas.canvas` and check for 404, which is racy.
- `nodeAtParentLookup(nodes, rect)` is the auto-parent helper for the editor. It picks the smallest enclosing block-node, not the first match, so a hotspot drawn inside a tiny block inside a giant one parents correctly.
- The side panel intentionally has two markdown sources: `node.text` (inline, from canvas.canvas) and `data/puzzles/<slug>.md` (legacy filesystem). The fallback chain is "inline first, fall back to fetch", which lets us keep per-puzzle md files in the repo for diffing while authoritative storage migrates inline.

## Arrow layer rebuild (Phase 2)

- "Orbit" projection is NOT a ray-intersect with the rect. The intuition is "gap by 6 px in the outward-normal of the side this anchor sits on." If you build it as `rayHitRect(rect, anchor, toward_other_endpoint)` and the anchor sits exactly on the perimeter, the ray immediately exits at t=0 and you offset in the wrong direction for any other-endpoint that lies inside the rect's half-space. Simpler and correct: detect which side the anchor is on (or `inferSide` from the rect centre) and add `sideNormal * gap`. This matters because the seed `arr_001/002/003` edges have anchors exactly on cardinal midpoints, so the bug shows up immediately.
- Routers stay pure: input = endpoints + side normals + obstacles + waypoints; output = vertex array. Connectors stay pure: input = vertex array + style; output = SVG `d` string. The Manager (`arrows.js`) owns the SVG nodes. Keeps each layer testable in isolation and avoids the old `arrows.js` mega-class problem where path generation, DOM, event handling, and edit UI were intermixed.
- For the `bindings` map index (`boundEdges: Map<nodeId, Set<edgeId>>`) — rebuild on every `setEdges()` and every endpoint mutation, not lazily. The performance cost is negligible (constant in edge count) and the alternative is bug-prone partial-update logic on every rebind/branch-add. `_rebuildBoundIndex()` is called five places in the layer; that's fine.
- Dangling endpoints store `fromPoint`/`toPoint` (absolute world coords) on the edge. `data-loader.normaliseEdge` must preserve those fields explicitly otherwise round-trips through localStorage drop the dangling state and the edge silently re-anchors to a missing node id (renders nothing). Phase 1's `normaliseEdge` only handled the side/binding/branches; we extended it here.
- The popover lives outside the SVG (appended to `document.body`). That means it does NOT block pan/zoom on the canvas because the canvas mousedown handler is bound to the canvas element itself, not to the document. The popover only swallows events that hit its own bbox.
- Double-click on a selected edge's path adds a waypoint. `_onDoubleClick` reads `data-id` off the target — only paths carry it (handles use `data-edge` or `data-block`). This means double-clicking a waypoint handle does NOT add another waypoint, which is the desired behaviour.
- Phase 2 left a `void jumpoverPathD` reference in `arrows.js _drawLabel()` after a refactor. The symbol was removed from the imports but the void-statement remained, which would throw `ReferenceError` at first render in any browser. JS-level smoke tests skip the SVG path entirely so this was latent. Lesson: when removing an import, grep the whole file for the bare identifier, not just usages that look intentional. Phase 3 removed the dangling reference.

## UX phase (Phase 3)

- The viewer's `setStatusFilter` used to filter by hiding (`_isVisible` returns false for non-matching). Phase 3 needs fading at 0.1 opacity, not hiding, and that fade has to apply both to the canvas-rendered hotspots and to the SVG edges. The cleanest split is: viewer renders at alpha 0.1 for nodes that don't match (still hit-testable for clicks), and the arrow layer applies an `opacity` SVG attribute to the path only when the filter is in fade mode AND neither endpoint node matches. Edges connecting at least one matching node stay full opacity, which is the requirement.
- The minimap renders at lowest LOD always, but its data source is the same `viewer.getHotspots()` array. Don't try to keep a separate copy of the world data in the minimap; subscribe to the viewer's notifier (transform, nodes, filter) and re-draw on each event. The viewer's `subscribe()` returns an unsubscribe fn for cleanup.
- LOD level is pure: `lodFromScale(scale) -> level`, `lodFlags(level) -> flags`. Wire that into both `viewer._draw` (for the canvas) and `arrows._draw` (for SVG). At zoom < 0.25 the canvas draws solid rects instead of `drawImage` and the arrow layer hides labels (already hidden at < 0.5 per spec).
- Keyboard handlers must skip when focus is on an input, textarea, select, or contenteditable element. Otherwise typing the letter "M" in the search bar would toggle the minimap. The `_shouldSkip(ev)` check is cheap and necessary. The two exceptions: `Esc` always works (closes overlays) and `Ctrl+K` should fire regardless (open palette from inside any field).
- Outline panel persistence is separate from the canvas snapshot. The outline maintains its own localStorage key (`arg_map_outline`) and is also exported as a separate `outline.json` file alongside `canvas.canvas` on Export. Mixing the two into the snapshot bloats every save and creates a contention point between dirty flags.
- Detective theme must change the viewport background, the canvas fill (for opaque areas), edge stroke, edge label appearance, and the toolbar/minimap/outline panel chrome. Doing it as a body class with `body.detective` selectors in a single `theme-detective.css` keeps the toggle reversible — there are no scripted style modifications to undo.
